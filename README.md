# cpp-elevator-simulator
以 C++ 實作的多電梯調度模擬器，包含 LOOK、代價式派車與等待時間統計。
1. 核心類別與關係定義
    • Passenger (乘客)：系統資料流動的最小實體。包含體重、起終點與各階段時間（屬性），作為系統計算平均等待與搭乘時間的基礎。
    • Elevator (電梯)：負責移動與載客。與 Passenger 之間為組合關係 (Has-a)，內部擁有一個 vector<Passenger> 。包含最大載重與當前移動狀態等屬性。
    • Floor (樓層大廳)：負責暫存等待中的乘客。與 Passenger 為聚合關係 (Has-a)，將等待乘客分為 upQueue 與 downQueue 兩個佇列。
    • Dispatcher (中央調度器)：系統的大腦。與 Elevator 為依賴關係 ( Uses-a)，負責計算任務代價並將指派請求傳送給電梯。
    • DataCollector (數據統計器)：收集所有完成搭乘的乘客實體，並於模擬結束時進行時間運算與產出報告。
    • Simulator (模擬主控台)：系統驅動核心，負責推進時間 (Tick)、呼叫亂數生成乘客並驅動各類別運作。
二、 程式特色與核心演算法
本系統不只滿足基礎的CRUD與移動邏輯，也導入了以下演算法與擬真機制，使模擬環境高度貼近真實：
1. 中央調度：代價評估演算法 (Cost-Based Dispatch)
調度器並非隨機派車，而是實作了代價評估機制。當大廳產生新請求時，Dispatcher 會要求每部電梯根據自身狀態計算「代價分數」。若電梯處於閒置，或移動方向與請求方向相同且處於「順路」位置，則代價極低；若方向相反，則加上極大的懲罰值，藉此確保指派效率最佳化。
2. 電梯移動：LOOK 掃描演算法
電梯的移動邏輯採用LOOK掃描演算法。電梯會保持當前方向持續移動並順路載客，直到該方向的前方已經沒有任何停靠請求時，才會切換方向或進入閒置狀態。
3. 擬真物理與人類行為模型
    • 常態分佈與動態亂數種子：使用 C++11 <random> 函式庫。並採用 std::time 動態種子解決舊版編譯器偽亂數定格問題。乘客的體重採用「常態分佈 (Normal Distribution)」，多數集中於 65kg，並有極端值產生，符合真實人類體重分佈。
    • 安全門延遲機制：實作車廂門安全機制。電梯每停靠一次樓層進行上下客，皆會觸發 5 個 Tick (秒) 的倒數計時器，期間電梯強制靜止。
    • 群聚效應與大廳效應：系統捨棄單一均勻分佈，加入人群大小不一定的群聚事件機率；並且設定 70% 的乘客起終點與 1 樓大廳相關，還原尖峰時刻壓力。
三、 程式執行方式與環境需求
    • 編譯環境：本系統需在支援 C++11 標準的環境下編譯 (因使用 <random> 函式庫與 auto 語法)。
    • 如何執行程式 (操作步驟)：
        1. 打開 Dev-C++ ，載入本專案之 elevators.dev 專案檔（或將所有 .h 與 .cpp 檔加入同一個專案中）。
        2. 點擊頂部選單的「工具 -> 編譯器選項」，在「編譯器指令」欄位中手動加入 -std=c++11 並按下確定。
        3. 按下 F11 (編譯並執行) 啟動程式。
        4. 程式啟動時會進入防呆設定選單，請依序輸入欲模擬的「樓層數」、「電梯數量」、「載重上限」、「模擬時間」與「乘客產生機率」。
        5. 設定完成後，系統將自動跑完模擬並印出最終數據報告。
四、 系統限制與未來可擴充 
本期末專題目前之樓層陣列對應為 1F 至 NF。在真實大樓中，常包含 B1、B2 等地下停車場樓層。若未來欲擴充此系統，計畫導入「樓層偏移量 (Floor Offset)」機制，將負數樓層 (如 B1 為 -1) 透過 index = floor + offset 的方式安全映射至陣列中，並於調度器中加入地下停車場至 1 樓大廳的專屬人流機率模型，以達到更全面的大樓模擬。
